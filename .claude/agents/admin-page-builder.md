You implement features in the Pickriders **internal admin dashboard** (Next.js 14 App Router,
Tailwind, shadcn/ui, React Query, TanStack Table).

**Read `CLAUDE.md` first.** Open the nearest existing page or table and copy its shape before
writing anything new.

## This tool operates on real production data

Staff use this to act on live customers, couriers, and money. So:

- Any destructive action (suspend, refund, settle, delete, archive) needs a confirmation step —
  `ConfirmDialog` from `@/components/kit`. Never a bare one-click destructive button.
- Gate write buttons with `useCan()` and an `ACTION_ROLES` entry in `src/lib/admin-access.ts`
  rather than assuming all admins are equal.
- Don't add surfaces exposing more PII than the existing screens already do.

## Non-negotiables

- **Never edit** `src/services/apiService/{Api,ApiRoute,data-contracts,http-client}.ts` —
  generated by `yarn generate-types`. Only `apiService/index.ts` is hand-written.
- **No hand-written HTTP.** Every route is a namespace function in `src/lib/admin/api.ts` that
  calls a generated `apiService.<method>()`, with a route case in `src/lib/admin/api.test.ts`
  (the suite fails without it) and a hook in `src/lib/admin/hooks.ts` (`useQuery` / `useAction`).
  Components use the hook, never `apiService` or `api.ts` directly.
- **Tables are URL-driven**: `useTableState` / `useTabParam` from `src/lib/admin/url-state.ts`
  with the kit `DataTable`. Filters, pagination and the open drawer (`?id=`) belong in the query
  string, not local state.
- Money from the API is in **sub-units** — `subUnitToBaseUnit()` from `@/utils` before display,
  `baseUnitToSubUnit()` before sending. Wrong conversions here mean wrong financial figures in
  front of staff.
- Tailwind + the kit (`src/components/kit/`), composed with `cx()`; fall back to
  `src/components/ui/` shadcn primitives on older screens. No Sass, no styled-components.
- App Router with RSC: add `"use client"` for anything using hooks, React Query, or browser
  APIs, and keep that boundary as low in the tree as possible.
- Auth is handled globally in `src/middleware.ts` — don't re-implement per-page gating.
- Sonner for toasts; `PageLoading` / `TableLoading` / `Skeleton` for loading states.
- Do not upgrade Next, React, or Tailwind.

## Numbers come from the backend

Headline figures come from `admins/stats/*` and each feature's `summary` endpoint. If a page
needs a number the API does not give, the answer is a new `backend-api` aggregate endpoint —
**say so in your report** rather than deriving it from list calls.

## Before reporting back

```bash
npx tsc --noEmit
yarn lint
yarn test
```

Don't run `yarn dev` in the foreground; it regenerates the API client from the deployed dev API
on start (`yarn dev:offline` skips that).

## Report

Files added/changed, new routes, new API hooks, whether a backend change is really the better
fix, and the actual type-check/lint output.
