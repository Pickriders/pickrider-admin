You implement features in the Pickriders **internal admin dashboard** (Next.js 14 App Router,
Tailwind, shadcn/ui, React Query, TanStack Table).

**Read `CLAUDE.md` first.** Open the nearest existing page or table and copy its shape before
writing anything new.

## This tool operates on real production data

Staff use this to act on live customers, couriers, and money. So:

- Any destructive action (suspend, refund, settle, delete) needs a confirmation step —
  `AlertDialog` from `src/components/ui/`. Never a bare one-click destructive button.
- Check permissions via `src/lib/admin-access.ts` rather than assuming all admins are equal.
- Don't add surfaces exposing more PII than the existing screens already do.

## Non-negotiables

- **Never edit** `src/services/apiService/{Api,ApiRoute,data-contracts,http-client}.ts` —
  generated by `yarn generate-types`. Only `apiService/index.ts` is hand-written.
- Never call `apiService` from a component — go through a hook in `src/api/{queries,mutations}`
  built on `useApiQuery` / `useApiMutation`. Export a `*_KEY` constant and invalidate it in
  related mutations.
- **Tables are URL-driven**: `useApiReactTableQuery`, `useTableUrlFilter`, `useURLQuery`,
  `useRowSelection`. Filters, pagination, and selection belong in the query string, not local
  state.
- Money from the API is in **sub-units** — `subUnitToBaseUnit()` from `@/utils` before display,
  `baseUnitToSubUnit()` before sending. Wrong conversions here mean wrong financial figures in
  front of staff.
- Tailwind + shadcn only; compose with `cn()` from `@/lib/utils`; reuse `src/components/ui/`
  primitives before writing anything bespoke. No Sass, no styled-components.
- App Router with RSC: add `"use client"` for anything using hooks, React Query, or browser
  APIs, and keep that boundary as low in the tree as possible.
- Auth is handled globally in `src/middleware.ts` — don't re-implement per-page gating.
- Sonner for toasts; `PageLoading` / `TableLoading` / `Skeleton` for loading states.
- Do not upgrade Next, React, or Tailwind.

## Before adding client-side aggregation

`src/api/queries/analytics.ts` already derives dashboard figures client-side because the backend
has no aggregate endpoints. It's fragile and chatty. If your task needs more of that, consider
whether a new `backend-api` endpoint is the right answer and **say so in your report** instead
of quietly deepening the workaround.

the foreground; note that it rewrites generated API types on start.
